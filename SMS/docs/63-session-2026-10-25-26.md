## 三、【未解决】跨版本遗留问题（单列）

### 3.1 舯段色差（miscolored fore/aft sections）

**现象**：部分船体（含原版 hull）在**复制出来的舯段**上出现边界锐利的暗色带；不同天气/光照下更明显。
原版几乎没有影子，所以历史上不暴露；duke 在 3.21.1+ 引入太阳与阴影后暴露。

**已排除（实测）**：

| # | 假设 | 结论 |
| --- | --- | --- |
| 1 | `hullData` 的 `sectioning` | ❌ CSV 206 条全 cyclical |
| 2 | 缺 `OnRenderersWasChanged` | ❌ 单点补调用无效 |
| 3 | `RefreshHull` 重写不完整 | ❌ 完整移植后仍在 |
| 4 | 装饰/场景光照 | ❌ `ConfigureForPreview` 已真正生效，色差不变 |
| 5 | **材质实例不同** | ❌ 复制段与原始段材质 **InstanceID 完全相同** |
| 6 | 阴影属性不同 | ❌ `cast/recv` 全一致 |
| 7 | **渲染器数量差异** | ❌ 差异只是 B0 多了 2 个**救生艇**渲染器 |
| 8 | **法线翻转** | ❌ `normals avg` 完全相同 `(-0.001, 0.012, 0.002)` |

**当前最有价值的线索（port45 探针）**：

```
B0（原始段）:   localScale=(1, 1, 1)         lossy=(0.73, 0.73, 0.73)
M0..M3（复制段）: localScale=(0.91, 1.016, 1)  lossy=(0.664, 0.741, 0.73)
```

即：`RefreshHull` 对**舯段**施加了 **非均匀缩放**（beam −9% / draught +1.6%）：

```csharp
Util.SetScaleX(section.transform, beam / 100f + 1f);     // 0.91
Util.SetScaleY(section.transform, draught / 100f + 1f);  // 1.016
```

**下一步（明天第一件事）**：把 MAT 探针扩展为遍历 **`hull.hullSections`（含 bow/stern）**，
对比首/尾段的 `localScale`：

| 若 | 结论 | 修复方向 |
| --- | --- | --- |
| 首/尾段 = `(1,1,1)`，只有舯段被缩放 | 段与段之间 X 方向差 9% ⇒ 接缝露出内壁 ⇒ **就是色带** | 把 beam/draught 缩放应用到**整个 hull**（或统一应用到所有段），而不是只缩放舯段 |
| 全部段都是 `(0.91,1.016,1)` | 缩放一致，色带另有原因 | 转向"阴影自遮挡"/`shadowBias` 方向 |

### 3.2 甲板装饰物不显示（port7 起）

**时间线（你回溯确认）**：

| 版本 | 装饰物 | 说明 |
| --- | --- | --- |
| port6 | ✅ 正常，覆盖率可调 | 原版模式 |
| **port7** | ❌ 消失 | **引入了 `Ship.RefreshHull` 全量替换** |
| port30–46 | ❌ 一直没恢复 | 期间多次猜测（Decor.Awake / RefreshDecor / 隐藏逻辑）均无效 |
| Beta6 | ✅ 正常 | duke 的实现里是好的 |

**已确认的事实**：

1. **生成逻辑就在 `Prefix_RefreshHull` 里**（Beta6 反编译 L1105-1119：`DeckProps` 容器 + `DeckProp` 模板 + poisson 布点）；
   我们的 `ShipRefreshHull.cs` L353-424 **也移植了这段**。
2. 日志显示 `[SMS.1.DECOR] 遮挡隐藏已禁用，decor=10` ⇒ `ship.decor` 里有 **10 个装饰件**（说明对象存在）。
3. 覆盖率设置 = **50%**（调到 100% 也无变化）⇒ 不是"覆盖率为 0 走销毁分支"。
4. 把 `RefreshDecor` 改成 Postfix、把隐藏逻辑关掉，**都不能恢复显示**。

**port47 已加入取证日志（明天用）**：

```
[SMS.1.PROP] enter: hull='...' coverage=50 updateSections=...
[SMS.1.PROP] done: DeckProps children=N
[SMS.1.PROP] Postfix_RefreshDecor called (n=..)
```

**三种可能，靠日志区分**：

| 日志 | 结论 | 下一步 |
| --- | --- | --- |
| 完全没有 `enter` | **构造器没走我们的 `RefreshHull`** | 说明装饰物原本由别的路径生成，被我们的 Patch 挡掉；需查构造器装载链 |
| 有 `enter`、`coverage=50`、`children=0` | 生成失败 | `Util.AttachInst(s.gameObject, "DeckProp", ...)` 模板找不到 / 抛异常 |
| 有 `enter`、`children>0` | 生成了但**不可见** | 位置/层级问题（`prop.transform.localPosition` 用了 `deck.transform.position.y`，而舯段被缩放后 deck 的 Y 可能偏移） |

### 3.3 `Decor.Awake` 的 `Sequence contains no elements`

| 项 | 内容 |
| --- | --- |
| 现象 | 主菜单/构造器/战斗加载时成对刷 `InvalidOperationException: Sequence contains no elements at Decor.Awake` |
| 根因 | 原版 `Decor.Awake` 对子渲染器做 `Enumerable.Aggregate`，空集合必抛；**异常在 IL2CPP 原生侧产生**，经 `Il2CppInterop.RaiseExceptionIfNecessary` 在托管 detour 之外抛出 |
| 已试 | Finalizer（❌ 拦不到）、Prefix 替代（✅ 消除日志，但**装饰物不显示**）、混合策略（❌） |
| 当前状态 | `decor_awake_guard=0`（**不介入**）⇒ 装饰物优先，但日志噪音保留 |
| 与 Beta6 的差距 | Beta6 用 Prefix **整体替代** `Awake`（重建 bounds/forceIgnoreX/forceOverlapX/children/layer）后**装饰物正常**；我们照搬却不行 ⇒ 说明我们缺了他实现里的某个内部注册步骤（反编译不可见） |
| 待办 | 等 §3.2 定位后一起处理；或对照 Beta6 二进制 IL 逐条补 |

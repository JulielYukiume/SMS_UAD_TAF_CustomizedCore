# 64 · 色差与甲板装饰物：**冻结决定**（2026-10-26）

> 决定：两个问题**暂停排查**，等 3.22 其余特性移植完成后，再用"与 Beta6 的整体差异比较"来收口。
> 本文记录冻结时的**全部已知信息**，避免以后重复调查。

---

## 1. 冻结理由（用户判断，已采纳）

| 观察 | 含义 |
| --- | --- |
| **OURBUILD**（从 Beta6 反编译重建）**没有**色差 | 说明该问题**能**通过反编译代码块重建被正确解决 |
| **sms.0** 也没有色差 | 同上 |
| 但**从 3.21.1 出发**（我们当前路线）已提交的 3.22 源码里**不含**对应解决方案 | 说明修复在**未提交的 Beta4+ 二进制**里，需要靠"反编译差异"来找 |
| Beta#3 有色差、Beta#4 无色差（用户提供对照截图） | 修复在 Beta3→Beta4 之间，**且表现为"色调/渲染方式"变化**，不是船体几何改动 |

⇒ 结论：与其继续盲猜单个机制，不如**等移植完成**后做一次 "OURBUILD vs 当前构建" 的**逐方法差异审计**。

## 3. 甲板装饰物（DeckProps）：**当前状态与已定位的问题**

### 3.1 时间线

| 版本 | 状态 |
| --- | --- |
| port6 | ✅ 正常（原版模式） |
| **port7** | ❌ 消失（引入 `Ship.RefreshHull` 全量替换） |
| port30–52 | ❌ 一直没恢复；期间多次误判（`Decor.Awake`、`RefreshDecor`、隐藏逻辑） |
| port53 | ⚠️ 生成数量正确，但**散布范围错误**（聚成一坨）——因 `deckBounds` 只覆盖最初选定的甲板 |
| **port54** | 散布算法已按用户规则重写（按高度分组 + 组内布点）+ 修掉一个致命异常 |

### 3.2 关键事实链（**收敛后的理解**）

| 事实 | 说明 |
| --- | --- |
| 生成逻辑在 **`Prefix_RefreshHull` 尾部**（Beta6 L1105-1119） | 我们已移植 |
| `deckPropCoverage` = 50，不是 0 | 不会走销毁分支 |
| 布点坐标必须与 `FindDeckAtPoint` 的坐标系一致 | port50 用"三级回退"解决（此前 61 个点全被判空） |
| **`UpdateDeckClutter` 会抛 `ArgumentOutOfRangeException`** | **旧实现按 `i += 2` 访问 `props[i+1]`**，而新算法生成数量任意（可能是奇数）⇒ 异常**中断整个装饰流程**。port54 已健壮化 |
| 用户补充：`DeckProps` 与**碰撞无关** | 它只是"甲板可放部件"的视觉暗示，只应在**甲板平面**上散布 |

### 3.3 用户给出的**正确散布规则**（port53 已实现）

1. 读取所有 `deckplace`（`BoxCollider`）的位置/旋转/尺寸；
2. **跳过绕 X 轴有旋转的甲板**（舰艏上翘段，不适合摆放）；
3. **按高度分组**（容差 ~0.75，一般 1–3 组）；
4. 每组取**总包围盒**；
5. 组内按包围盒范围**均匀布点**（Poisson），逐点放置到该组高度。

日志：`[SMS.1.PROP] detail: decks=N skippedRot=K groups=G sep=.. placed=P props=M`

### 3.4 冻结后的下一步（收口阶段）

| 步骤 | 内容 |
| --- | --- |
| 1 | 修掉 port54 的异常后，先确认"装饰物能否生成"（不追求散布完美） |
| 2 | 与 Beta6 的 `Prefix_RefreshHull` 装饰块**逐行对照**（我们缺/偏了哪几步） |
| 3 | 若仍不行，考虑把 `Decor.Awake` 也改为 Beta6 的整体替代 + 补齐缺失的内部注册 |

## 4. 冻结期间的纪律

| 规则 | 原因 |
| --- | --- |
| **不再**为色差/装饰物单独发版本 | 避免把移植进度拖死 |
| 移植其它特性时**不要动** `ShipRefreshHull` 的装饰块与 `DecorFix` | 防止互相干扰 |
| 若新移植导致这两个问题**恶化**（例如异常刷屏、卡顿），允许**立刻修异常**，但不追求功能恢复 | 保证可玩性 |
| 收口审计时，用 **OURBUILD（反编译重建版）** 作为参照做 diff | 用户判断：OURBUILD 无此二问题 |
